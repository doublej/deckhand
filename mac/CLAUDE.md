# The Mac app

## What this is

`DeckhandMac`: the manager's conversation for the person at the Mac, in the menu bar and in a
window, and a notification for every card the daemon raises for a session. Generated by XcodeGen
from `../project.yml` like the phone's target; `just mac` builds it into `~/Applications` and
starts it. `ManagerLine` and `ManagerStarters` are the phone's own files, compiled into both.

`Desk` is all of its state and its one poll; `Notifier` shows what the poll found;
`ManagerPanel` draws the conversation in both places; `Pairing` is the address, token and login
item. `AppActivation` is utt's, copied with its measurements.

## Invariants

- **A poll from here says whether a panel is being looked at** (`GET /manager?watching=`).
  Every manager poll used to tell the daemon a panel was open, which stops it pushing replies to
  the phone — so a Mac app polling from the menu bar all day would silently have turned the
  phone's manager notifications off. A panel counts while its window `appearsActive`; when the
  last one stops, `POST /manager/away` says so at once.
- **Session notifications are the daemon's cards, never decided here.** `GET /alerts` is the
  same `push.announce` the Lock Screen gets, so a folder set quiet is quiet on both and there is
  no second interruption policy to drift. Only `asking` makes a sound. `AlertCursor`
  (DeckhandKit, tested) is what keeps them honest: the first poll is history, and a newest id
  below the held one is a daemon restart.
- **Loopback by default, token off disk.** On this Mac it talks to `127.0.0.1` with the token
  read from `~/Library/Application Support/Deckhand/token`, so there is nothing to pair — and
  loopback matters beyond convenience: `presence.seen` takes every other address for the phone,
  which would put utt's cover up over a Mac somebody is sitting at. Pointed at another Mac's
  daemon, these polls *do* count as the phone; that is the known ceiling.
- **A regular app, not `LSUIElement`.** It has a Dock icon and its own Cmd-Tab entry, and
  opening it again (Dock, Cmd-Tab, Spotlight) shows the window through
  `applicationShouldHandleReopen`. The window never opens at launch, because it starts at login.
- **A session the manager names is a `deckhand://sessions/<id>` link**, `CardLink`'s shape, put
  in on this side by `ManagerLinks`: a name the manager wrote in bold or as code that is one of
  this Mac's live sessions. Asked in its prompt to write the links itself, it wrote bold anyway —
  so the link is not the model's to remember. The panel's `openURL` sends a click to
  `POST /sessions/{id}/focus`, which brings that session's iTerm window and tab forward. The
  manager still never types into a pane — the person clicks.
- **No talk mark.** utt dictates into any field on this Mac, this one included.

## Verification

`just build` builds it beside the phone's app; `just mac` installs and starts it. Notifications
need the signed build: an unsigned app is refused by `UNUserNotificationCenter`.
